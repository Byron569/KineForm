**最值得参考的 3 个项目**：
1. **Sports2D**（287★，活跃）— 与 RTMPose halpe26 技术栈完全同源，单视频→2D 关键点轨迹+关节角，定位与用户需求几乎重合

### 5. MMPose 全家桶安装（多轮排障）

依次解决：
1. **chumpy 构建失败**（mmpose 传递依赖，构建需 pip）→ 装 pip/setuptools 后 `--no-build-isolation` 重装
2. **mmdet 3.3.0 要求 mmcv<2.2.0** → 从 2.2.0 降到 **mmcv 2.1.0**
3. **numpy 被依赖解析器升到 2.4.6** → torch 2.1.2 与 numpy 2.x 二进制不兼容，锁定 **numpy 1.26.4 + opencv 4.11.0.86**（constraints.txt）
4. **mmcv 轮子下载被 CDN 中断** → curl 断点续传手动下载再本地安装
5. **pkg_resources 缺失**（新 setuptools 84 移除，mmengine 依赖它）→ 降级 `setuptools<81`（80.10.2）

最终环境：`torch 2.1.2+cu121 / mmcv 2.1.0 / mmdet 3.3.0 / mmpose 1.3.2 / mmengine 0.10.7 / numpy 1.26.4 / opencv 4.11.0.86`

## 二、关键技术决策记录

| 决策点 | 结论 | 理由 |
|---|---|---|
| 姿态模型 | RTMPose-m Halpe-26（保留，不换） | halpe26 六个脚部点是稀缺能力；精度第一梯队（跑步角度 RMSE 5.62°、跳跃 ICC 0.985） |
| Python 版本 | 3.11.9 | mmcv Windows 预编译轮子最高 cp311 |
| torch 版本 | 2.1.2+cu121 | mmcv 官方 Windows 轮子覆盖的最新组合 |
| numpy | 锁定 1.26.4 | torch 2.1.2 与 numpy 2.x 二进制不兼容 |
| mmcv | 2.1.0（不用 2.2.0） | mmdet 3.3.0 要求 mmcv<2.2.0 |
| setuptools | <81 | mmengine 依赖 pkg_resources（≥81 已移除） |
| 下载源 | 阿里云镜像 pytorch-wheels | 官方源/pypi 在用户网络下不稳定 |
| ffmpeg | imageio-ffmpeg 内置 | 系统无 ffmpeg/ffprobe |
| scope 污染 | detect 前 init_default_scope('mmdet') | mmpose 推理会切换全局 scope |
| VFR 判定 | 无法确凿证明 CFR 一律转 | 探测降级时的保守安全策略 |
| 帧数对齐 | 输出帧数严格=关键点行数 | 保证逐帧对应（源读不尽时用上一帧补齐并 warning） |
